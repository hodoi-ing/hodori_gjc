# 🚧 HWP Zero-Touch 5대 장애물 및 구체적 해결 설계도 (Implementation Blueprint)

> **[목적]**
> 본 문서는 HWP 자동화를 '완전 무인화(Zero-Touch)'로 구축할 때 마주하는 5대 치명적 요인을 해결하기 위한 **구체적인 코드 레벨의 아키텍처와 로직**을 정의한다.

---

## 1. 팝업(Dialog) 지옥과 무한 대기
* **[현상]** OLE 실행 중 폰트 누락, 업데이트 경고창이 뜨면 파이썬 스크립트가 무한정 멈춤(Hanging).
* **[구체적 해결 설계: Aggressive Timeout & API 억제]**
  1. **API 레벨 억제:** `pyhwpx` 실행 시 `hwp.SetMessageBoxMode(0x20000)` API를 호출하여 한글 내부의 모든 경고창을 자동 통과시킨다.
  2. **강제 킬 스위치 (Timeout Wrapper):** 팝업 제어가 실패할 최악의 경우를 대비해, 문서 처리 함수에 `@timeout(60)` 데코레이터를 씌운다. 60초 초과 시 `os.system("taskkill /f /im hwp.exe")` 명령어를 쏴서 강제로 한글 프로세스를 죽이고 에러를 반환하여 메인 파이프라인이 멈추지 않게 방어한다.

## 2. 셀 병합 시 XML 붕괴 현상
* **[현상]** XML 파서로 표 구조를 직접 건드리면 파일 포맷이 박살남.
* **[구체적 해결 설계: 데이터 타입 기반 자동 라우팅 (Interface Contract)]**
  * 브릿지 클래스(`hwp_bridge.py`)의 `fill_data(data)` 메서드 하나만 외부에 노출한다.
  * **라우팅 로직:** 
    * `type(data) == str` 이면 무조건 `python-hwpx-automation` (XML) 엔진으로 빠져서 누름틀만 치환한다.
    * `type(data) == list` (배열) 이면 표에 줄을 추가하려는 의도로 간주하고, 내부적으로 OLE 워커(`hwp_ole_worker.py`)를 서브프로세스로 호출해 한글 앱을 띄워 처리한다.

## 3. 누름틀(Field) 폰트 초기화 버그
* **[현상]** 파이썬으로 텍스트를 주입하면 템플릿의 예쁜 폰트가 바탕체 10pt로 초기화됨.
* **[구체적 해결 설계: StyleID 보존 주입 로직]**
  * **XML 방식:** 정규식이나 단순 `replace`를 절대 쓰지 않는다. XML 파서로 누름틀 노드(`<hp:ctrl>`) 안의 `<hp:t>` (텍스트 엘리먼트)를 찾은 뒤, 해당 노드를 삭제하지 않고 `text` 속성값만 비운 뒤 새 글자를 주입한다. (부모의 StyleID 상속 유지)
  * **OLE 방식:** `hwp.SetText` 대신 무조건 `hwp.PutFieldText("필드명", "데이터")` API만 사용한다. 이 API가 내부적으로 폰트 포맷 유지를 보장한다.

## 4. 멀티쓰레딩 시 한글 프로세스 충돌(Crash)
* **[현상]** 다수의 문서 생성 요청이 동시에 들어올 때 한글 백그라운드 프로세스가 엉켜서 터짐.
* **[구체적 해결 설계: FileLock 기반 싱글톤 워커 (Singleton Worker)]**
  * 무거운 Celery나 Redis 대신, 파이썬 기본 라이브러리인 `filelock`을 도입한다.
  * OLE 엔진을 띄우는 함수 진입 시 `with FileLock("hwp_ole.lock"):` 으로 감싼다.
  * 동시 접속자가 10명이어도, 락(Lock)을 획득한 1번 작업이 끝날 때까지 나머지 9개는 대기열에서 순차적으로 기다리게 되어 한글 프로세스 꼬임을 100% 방지한다.

## 5. 구버전 HWP ↔ 신버전 HWPX 파편화
* **[현상]** 파이프라인에 구버전 `.hwp` 파일이 들어오면 XML 파서가 터짐.
* **[구체적 해결 설계: Magic Number 검사기 (Preprocessor)]**
  * 확장자 `.hwp`를 믿지 않는다. 바이너리 파일을 읽어서 헤더의 **Magic Number(`D0 CF 11 E0` - OLE 포맷 시그니처)**를 검사한다.
  * 매직 넘버가 OLE 포맷이면, 파이프라인 입구에서 `hwp_converter.py`를 즉시 실행하여 `hwp.SaveAs("파일.hwpx", "HWPX")`로 포맷을 강제 세탁한 후 메인 로직으로 넘긴다.
