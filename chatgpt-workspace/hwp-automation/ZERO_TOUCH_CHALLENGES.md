# 🚧 HWP Zero-Touch 5대 장애물 및 해결 아키텍처

> **[목적]**
> 본 문서는 HWP 자동화를 '완전 무인화(Zero-Touch)'로 구축할 때 마주하는 5대 치명적 요인을 영구적으로 기록하고, 이를 코드로 우회/해결하기 위한 아키텍처 방향성을 정의한다.

---

## 1. 팝업(Dialog) 지옥과 무한 대기
* **[현상]** 로컬 한글(hwp.exe) OLE 실행 중 폰트 누락, 업데이트, 파일 손상 경고창이 뜨면 파이썬 스크립트가 영원히 멈춤(Hanging).
* **[해결 방향: Headless & Silent Mode 강제]**
  * `pyhwpx` 초기화 시 `Hidden=True` 속성을 강제하여 GUI 창을 띄우지 않는다.
  * 한글 API의 `SetMessageBoxMode(0x20000)` (또는 해당하는 경고창 무시 플래그)를 호출하여 **모든 팝업을 무시하고 기본값(확인/취소)으로 자동 통과**시키도록 브릿지 클래스에 하드코딩한다.

## 2. 셀 병합 시 XML 붕괴 현상
* **[현상]** 클라우드 환경에서 가볍게 처리하기 위해 `hwpx-kit` 등 XML 파서로 표에 행을 추가하거나 병합하면 문서 전체 포맷이 깨짐.
* **[해결 방향: 관심사의 완벽한 분리]**
  * **텍스트/누름틀 삽입:** 무조건 XML 파서(`python-hwpx-automation`) 사용 (안전함).
  * **표 구조 변경(추가/병합/서식):** XML 파서의 표 조작 기능을 완전히 차단(금지)하고, **표 구조 변경이 감지되면 무조건 로컬 OLE(`pyhwpx`) 엔진으로 라우팅**하여 한글 프로그램 자체가 계산하도록 책임을 넘긴다.

## 3. 누름틀(Field) 폰트 초기화 버그
* **[현상]** 템플릿에 예쁜 폰트를 지정해놔도, 파이썬으로 텍스트를 주입하는 순간 바탕체 10pt로 초기화됨.
* **[해결 방향: Style 보존 주입 로직]**
  * **템플릿 규칙:** `TEMPLATE_PROTOCOL.md`에 명시한 대로, 글자를 드래그해서 폰트를 바꾸는 것이 아니라 **'누름틀 속성' 자체에 서식을 고정**하도록 템플릿 작성자에게 강제.
  * **코드 규칙:** 데이터 삽입 시 단순히 텍스트 노드를 갈아끼우는 것이 아니라, 기존 텍스트 노드의 부모가 가진 `<hp:t>` (텍스트 속성) 스타일 ID를 그대로 상속받도록 치환 로직을 정교화한다.

## 4. 멀티쓰레딩 시 한글 프로세스 충돌(Crash)
* **[현상]** 다수의 문서 생성 요청이 동시에 들어올 때 OLE 방식을 쓰면 한글 백그라운드 프로세스가 엉켜서 PC 메모리가 터짐.
* **[해결 방향: 싱글 워커 태스크 큐 (Task Queue) 구축]**
  * 문서 생성 요청을 병렬(동시)로 처리하지 않는다. 
  * 백그라운드에 가벼운 작업 대기열(Queue) 시스템을 두고, **Worker(한글 프로세스)는 무조건 한 번에 1개의 문서만 순차적으로 꺼내서 작업**하도록 아키텍처를 강제한다. (속도보다 '절대 안 뻗는 안정성' 우선)

## 5. 구버전 HWP ↔ 신버전 HWPX 파편화
* **[현상]** 파이프라인에 구버전 `.hwp` 파일이 들어오면 XML 파서가 터짐.
* **[해결 방향: 전처리 컨버터(Preprocessor) 노드 배치]**
  * 메인 파이프라인(문서 조작) 앞단에 **검문소**를 둔다.
  * 확장자나 Magic Number를 검사하여 `.hwp` 파일이 들어오면, 본 작업 시작 전 무조건 OLE 엔진을 띄워 `.hwpx`로 `SaveAs(다른 이름으로 저장)` 변환부터 시킨다. 
  * 메인 파이프라인은 **오직 `.hwpx` 포맷만 입력으로 받도록 일원화**한다.
