# 🚧 HWP 자동 구간 기술 장애물 해결서

> **[운영 모델]**: 전체 워크플로의 승인 규칙(구조 변경 전 승인 게이트)은 `SEMI_AUTOMATION.md` 를 따른다.
> **[엔진 실태]**: 현재 엔진은 전부 XML 기반이다 — 내용 주입은 `paragraph_patch`/`fill_cells`, 구조 변경은 `apply_table_ops`. Windows/OLE는 더 이상 필요하지 않다.

---

## 1. 구형 HWP 바이너리 입력 차단
* **[현상]** 구형 `.hwp`(OLE2, 매직넘버 `D0 CF 11 E0`)는 XML 파서가 못 읽는다.
* **[해결]** 입구에서 실제 바이트 시그니처로 감별 → `.hwpx` 변환 후에만 메인 로직 진입.

## 2. 중첩 표(표 안의 표) 구조 변경 불가
* **[현상]** 표 안에 표가 들어있으면 `apply_table_ops`가 구조 변경을 거부한다(fail-closed).
* **[해결]** 거부 사유를 사용자에게 정직하게 보고하고, 내용 채우기(`fill_cells`)만으로 가능한 대안을 제안한다.

## 3. 표 병합/분리 시 검증 실패
* **[현상]** `merge_table`은 컬럼 수(colCnt) 불일치나 두 표 사이 실제 텍스트가 있으면 거부한다. `split_table`은 병합 셀이 경계를 가로지르면 거부한다.
* **[해결]** `--plan`(dry-run)으로 승인 전에 전후 dims와 거부 사유를 먼저 보여주고, 승인 후에만 `--apply`로 실행한다.

## 4. 서식/폰트 손상
* **[현상]** 단순 문자열 치환을 쓰면 폰트·서식이 깨진다.
* **[해결]** `paragraph_patch`(일반 문단)와 `fill_cells`(표 셀) 모두 바이트 보존(byte-splice) 방식이라 원본 서식이 자동 보존된다.

## 5. 미치환 플레이스홀더 잔여
* **[현상]** `{{키}}` 중 일부가 템플릿에 없거나 매핑이 누락되면 빈칸이 남는다.
* **[해결]** `--fill` 결과의 `unmatched` 목록으로 누락 키를 보고하고, `verify_integrity`가 미치환 `{{...}}` 잔여를 검출한다.
