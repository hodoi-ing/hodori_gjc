# 🤝 HWP 반자동화 (Semi-Automation, Human-in-the-Loop) 운영 규약

> **[목적]**
> "지시할 때마다 사람이 타깃 문서를 열어보지 않아도, 정해진 양식의 표 안에 내용이 자동으로 정리되는" 워크플로를 정의한다.
> 원칙은 단 하나다. **내용은 자동으로, 구조는 승인 후에.**

---

## 1. 사용자 지시 흐름

사용자가 "A 문서와 B 문서를 읽어서, C 문서의 표에 맞춰 정리해 줘"라고 지시한다.

```text
[사용자 지시]
   ↓
[1단계: 자동] 소스 문서 읽기 (syhwp)
   ├─ A.hwpx / B.hwpx 의 텍스트·표 데이터를 추출
   └─ 타깃 C.hwpx 의 표/누름틀 항목(필드명) 파악
   ↓
[2단계: 자동] 값 매핑 및 주입
   ├─ 소스 데이터 → 타깃 셀/필드 값으로 변환
   └─ 표·누름틀 구조는 그대로 두고 '값'만 채운다
   ↓
[3단계: 분기] 이 작업이 '구조 변경'을 필요로 하는가?
   ├─ 아니오 → [자동] 검증 → _수정본 반환 (종료)
   │
   └─ 예 (표 병합·행/열 추가·셀 병합·열 삭제 등)
        ↓
        [승인 게이트] 사용자에게 계획 제시
        ├─ 실행할 구조 변경 내용(ops) + 왜 필요한지(근거)를 명시
        └─ 승인 대기 (진행 여부 질문)
            ├─ [승인] → [자동] XML(apply_table_ops)로 구조 변경 실행 → 검증 → 완료
            └─ [거부] → 아무것도 변경하지 않음 (계획 폐기, 문서 무변경)
```

## 2. 3가지 불변 규칙

1. **내용 주입은 기하 구조를 절대 바꾸지 않는다.**
   타깃 표의 행·열 개수, 셀 병합, 누름틀 위치는 그대로 유지하고 값만 교체한다.
2. **구조 변경은 반드시 승인 게이트를 통과한 뒤에만 실행된다.**
   승인 전까지는 계획(설계도)만 존재하고, 테이블/문서에 어떤 변경도 가하지 않는다.
3. **모든 작업은 `_수정본` 복사본에서 수행된다.**
   원본 문서는 어떤 실수에도 손상되지 않는다.

## 3. 에이전트 행동 수칙 (승인 게이트 규칙)

- 사용자가 "표 합쳐서", "행 추가해서", "셀 병합해서" 같은 **구조 변경을 동반한 요청**을 하면,
  에이전트는 즉시 실행하지 않는다.
- 먼저 다음을 사용자에게 제시하고 **진행할지 명시적 승인을 받는다.**
  ```
  [구조 변경 요청]
  대상: C.hwpx 의 매출표 (sales_table)
  작업: 2개 표 병합 + 상단 헤더 셀 병합 1건
  근거: 소스 데이터가 2개 표로 분리되어 있어 1개로 합쳐야 정리 가능
  진행할까요? (승인/거부)
  ```
- 승인 받기 전에는 `plan_structural_change()` 계획만 만들고 실행하지 않는다.
- 거부 시 계획을 폐기하고, 내용 주입만으로 가능한 대안을 제안한다.

## 4. 관련 문서

- `TEMPLATE_PROTOCOL.md` — 타깃 양식(누름틀/표 이름) 작성 규칙
- `ZERO_TOUCH_CHALLENGES.md` — 자동 구간에서 맞닥뜨리는 기술 장애물 해결서
- `hwp_bridge.py` — 승인 게이트를 구현한 `PlannedChange` 클래스
