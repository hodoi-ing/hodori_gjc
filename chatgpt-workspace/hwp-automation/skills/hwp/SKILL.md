# hwp — HWP/HWPX 반자동화 스킬 (Semi-Automation, HITL)

HWP 파일을 다루는 모든 요청은 이 스킬의 계약을 따른다.
세부 규격: `chatgpt-workspace/hwp-automation/` 의
`SEMI_AUTOMATION.md`(운영 규약), `ZERO_TOUCH_CHALLENGES.md`(기술 장애물),
`TEMPLATE_PROTOCOL.md`(양식 규칙), `hwp_bridge.py`(래퍼).

## 1. 운영 모델: 내용은 자동, 구조는 승인

1. **자동 구간** — 여러 소스 문서(A, B)를 `syhwp`로 읽고, 타깃 문서(C)의
   표 셀/누름틀에 **값만** 주입한다. 표/누름틀의 기하 구조(행·열·병합·위치)는 절대 바꾸지 않는다.
2. **승인 게이트** — 표 병합, 행/열 추가, 셀 병합, 열 삭제 같은 **구조 변경**이 필요한 상황이
   오면 즉시 실행하지 말고 `plan_structural_change()`로 계획만 만든 뒤,
   사용자에게 [대상/작업/근거]를 제시하고 **명시적 승인을 받는다.** 승인 전 문서 변경 금지.
3. **거부 시** — 계획을 폐기하고 내용 주입만으로 가능한 대안을 제안한다.

## 2. 도구 라우팅 (반드시 준수)

| 작업 유형 | 예시 | 엔진 |
|---|---|---|
| 읽기 / 요약 / 분석 | "A, B 문서 읽고 정리해 줘" | `syhwp` (순수 파서, OS 무관) |
| 내용 주입(셀/누름틀) | "C 문서 표에 값만 채워줘" | `python-hwpx-automation` / `hwpx-kit` (XML) |
| 구조 변경(병합/행 추가) | "표 합치고 행 추가해 줘" | `pyhwpx` (OLE) — **승인 게이트 필수** |

- 입력 `str`/`dict` → 내용 주입(XML). 입력 `list` → 구조 변경 후보(OLE) → 승인 게이트.
- 구형 `.hwp`(바이너리)에 XML 치환은 **금지**. OLE 변환 후 진행하거나 에러를 보고한다.
- 형식 판별은 확장자가 아니라 바이트 시그니처(`D0 CF 11 E0`)로 한다.

## 3. 실행 프로토콜

1. `HWPBridge`를 써서 `_수정본` 복사본에서만 작업한다. 원본은 절대 덮어쓰지 않는다.
2. 구조 변경 계획은 `plan_structural_change()` → `approve()` 승인 후에만 실행한다.
3. 작업 후 `verify_integrity()`로 스스로 검수한다:
   - HWPX: ZIP 무결성 + 미치환 필드(`{{...}}`) 잔여 검사
   - HWP(OLE): 재열기 검증이 없으면 `NotImplementedError`로 명시적 실패
4. 완료 보고는 `IM_NOT_AI.md` 톤앤매너를 따른다. 로봇 어투 금지.

## 4. HWPX 자동화 비상 대응 (지옥의 5대 장애물)

- **팝업 무한 대기**: `SetMessageBoxMode` 억제 + `func-timeout`(60s) + `taskkill /f /im hwp.exe`
- **XML 표 붕괴**: 표 구조는 절대 XML로 직접 만지지 않는다. OLE엔진으로 라우팅
- **폰트 초기화**: `<hp:t>` 노드 삭제 금지, StyleID 상속 유지한 채 텍스트만 교체
- **멀티쓰레딩 충돌**: OLE 접근은 `filelock` 싱글톤 워커로 순차 처리
- **포맷 파편화**: 파이프라인 입구에서 HWP→HWPX 변환 후에만 메인 로직 실행
