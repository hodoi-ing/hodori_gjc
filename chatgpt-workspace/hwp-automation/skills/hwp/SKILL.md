# hwp — HWPX 반자동화 스킬 (실동작)

이 스킬은 문서만 늘어놓는 게 아니라 **로컬에서 실제로 돌아가는 엔진**을 호출한다.
핵심 원칙: **내용은 자동으로, 구조는 승인 후에.**

## 1. 실제 호출 방법 (GJC가 꼭 이대로 실행)

엔진 경로: `/home/hodol/.gjc-free/hwp/hwp_bridge.py` (python3, 의존성 설치 완료)

```bash
# 1) 템플릿의 {{키}} 플레이스홀더를 값으로 채우기 (표 셀 포함, 구조 불변)
python3 /home/hodol/.gjc-free/hwp/hwp_bridge.py --fill 문서.hwpx '{"user_name":"홍길동","date":"2026-08-26"}'

# 2) 문서 읽기/분석 (문단+텍스트를 JSON으로 추출)
python3 /home/hodol/.gjc-free/hwp/hwp_bridge.py --read 문서.hwpx

# 3) 문서 무결성/미치환 검사
python3 /home/hodol/.gjc-free/hwp/hwp_bridge.py --verify 문서.hwpx
```

- 출력은 항상 `<원본>_수정본.hwpx`로 생성된다. **원본은 절대 안 바뀐다.**
- 템플릿에는 `{{키}}` 플레이스홀더를 넣어둔다. (표 셀·누름틀 위치 모두 `{{키}}` 문자 치환)
- `--fill` 결과 JSON의 `unmatched`에 남은 키가 있으면 그 키는 템플릿에 없던 것이다.

## 2. 운영 규칙 (내용 자동 / 구조 승인)

1. **내용 주입**: `--fill`은 표·누름틀의 기하 구조(행·열·병합·위치)를 절대 바꾸지 않고
   텍스트만 바꾼다. (바이트 보존 `paragraph_patch` 사용)
2. **구조 변경 승인 게이트**: 표 병합, 행/열 추가, 셀 병합, 열 삭제가 필요하면
   즉시 실행하지 말고 사용자에게 [대상/작업/근거]를 제시하고 명시적 승인을 받는다.
   - 이 PC(WSL2/Linux)에서는 OLE(Windows+한글)가 없어 구조 변경은 **실행 불가**다.
   - 구조 변경이 필요한 순간에는 "Windows + 한글이 필요합니다"라고 정직하게 보고하고,
     내용만으로 가능한 대안을 제안한다.
3. 거부 시 계획을 폐기하고 문서는 무변경이다.

## 3. 비상 대응 (기술 장애물)

- XML 표 붕괴: 표 구조는 `--fill`(내용 치환)로만 만지고, 구조 변경은 절대 XML로 직접 하지 않는다.
- 폰트/서식 보존: `paragraph_patch`가 바이트 보존 방식이므로 원본 서식이 유지된다.
- 구형 `.hwp`(바이너리, `D0 CF 11 E0`)는 XML 치환 불가 → 먼저 `.hwpx`로 변환 필요.
