# AI Trend Researcher — 카드뉴스형 조사 MVP

## 목적
X, Threads, Reddit, GitHub에서 발견한 AI 관련 정보를 모아 주제별로 교차검증하고, 읽기 쉬운 카드뉴스형 텍스트 리포트로 보여준다.

## 사용 방식
사용자가 조사할 주제와 원하는 카드 수를 지정한다.

예:
- `오늘 AI Agent 이슈 5개`
- `이번 주 AI 개발 트렌드 10개`
- `Codex 관련 실제 프로젝트 7개`

지정한 개수만큼 핵심 항목을 선정한다. 개수는 고정하지 않는다.

## 카드 구성
각 카드는 다음 순서를 기본으로 한다.

1. `CARD NN` + 제목
2. 한 줄 요약
3. 무엇이 일어나고 있는지
4. X / Threads / Reddit / GitHub 등 출처별 신호
5. 작성자(가능한 경우 핸들/ID 포함)
6. 원문 URL
7. 신호 강도
8. 호도리에게 어떤 의미가 있는지

## 조사 원칙
- X / Threads: 최신 커뮤니티 반응과 작성자 확인
- Reddit: 실제 사용자 경험과 토론 확인
- GitHub: 실제 프로젝트 존재 및 활동 확인
- 뉴스/논문: 중요한 주장과 사건의 교차검증
- 실제 데이터와 AI의 해석/추정을 명확히 분리한다.
- 작성자를 확인할 수 있으면 반드시 기록한다.
- 원문 URL을 가능한 한 보존한다.
- 같은 사건을 여러 출처에서 발견해도 중복 카드를 만들지 않는다.

## 결과 형식
이미지 파일을 생성하지 않는다. Markdown/텍스트로 카드뉴스처럼 읽히도록 구성한다.

예시:

```text
# 🛰️ 오늘의 AI Radar
2026-08-25 · AI 개발

## 🟦 CARD 01
### AI Agent가 개발환경을 직접 다루기 시작했다

한 줄 요약
> ...

무슨 일이야?
> ...

🗣️ X — 작성자: @example
🔴 Reddit — 작성자: u/example
🧑‍💻 GitHub — 작성자: example/project

🔥 신호: 강함

🎯 호도리에게
> ...
```

## 데이터 저장 원칙
- GitHub에는 코드, 설계, 규칙만 저장한다.
- 검색할 때마다 원문 데이터를 GitHub에 누적하지 않는다.
- 이미지/스크린샷/원문 대량 저장을 하지 않는다.
- 조사 결과는 기본적으로 대화에서 보여주며, 장기 보관이 필요할 때만 별도 저장을 검토한다.

## MVP 단계
- 웹/API 자동 수집은 아직 넣지 않는다.
- ChatGPT가 실제 웹 검색으로 자료를 찾고 카드 형식으로 정리하는 방식을 먼저 검증한다.
- 여러 번 사용한 뒤 필요한 필드와 평가 기준을 확정한다.
- 그 다음 자동 수집/API 연동 여부를 결정한다.
