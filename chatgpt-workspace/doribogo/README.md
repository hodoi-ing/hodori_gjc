# 🛰️ 도리보고 (Doribogo)

> 요리보고 저리보고, **도리보고!**

AI 생태계에서 최근 무슨 일이 벌어지고 있는지 여러 곳을 돌아다니며 찾아보고, 서로 다른 이슈를 카드별로 정리한 뒤 관련 사이트의 반응까지 한눈에 보여주는 조사 프로젝트다.

단순한 뉴스 요약기가 아니다.

**주제 자체의 설명은 짧게 끝내고, 그 주제 안에서 최근 실제로 벌어진 서로 다른 변화·사건·논쟁·문제를 찾아내는 것**이 핵심이다.

---

## 📁 프로젝트 위치

이 프로젝트는 `hodori_gjc` 저장소의 아래 폴더에서 관리한다.

```text
chatgpt-workspace/
└── doribogo/
    └── README.md
```

`chatgpt-workspace`는 ChatGPT와 호도리가 함께 아이디어를 검증하고 작은 실험을 진행하는 작업 공간이다.

현재 도리보고는 **코드를 크게 만드는 단계가 아니라 조사 방식과 결과 형식을 검증하는 MVP 단계**다.

---

# 🎯 도리보고가 하는 일

도리보고는 크게 두 가지 방식으로 사용할 수 있다.

## DRT — 요리조리 보고와라!

**Dori + Topic**

사용자가 특정 주제를 정해주면 그 대상을 요리조리 살펴본다.

예:

```text
DRT
주제: OpenCode Go
개수: 5
기간: 최근 7일
```

결과는 다음과 같은 흐름이다.

```text
주제 입력
  ↓
대상에 대한 짧은 설명
  ↓
여러 소스 조사
  ↓
최근 이슈 발견
  ↓
서로 다른 이슈끼리 분리
  ↓
각 이슈를 다시 깊게 확인
  ↓
사이트별 반응 한줄평
  ↓
도리보고 카드 생성
```

## DRI — 이슈보고 저리보고!

**Dori + Issue**

특정 대상을 정하지 않고, 도리보고가 여러 소스를 돌아다니며 최근 이슈를 찾아온다.

예:

```text
DRI
분야: AI
개수: 5
기간: 오늘
```

흐름은 다음과 같다.

```text
여러 소스 탐색
  ↓
최근 자료 수집
  ↓
비슷한 자료끼리 묶기
  ↓
하나의 이슈인지 판단
  ↓
중요도·최근성·출처 다양성 확인
  ↓
이슈 후보 선정
  ↓
각 이슈를 다시 조사
  ↓
카드 생성
```

### 두 모드의 차이

| 모드 | 역할 |
|---|---|
| **DRT** | 내가 주제를 준다 → 도리보고가 조사한다 |
| **DRI** | 주제를 정하지 않는다 → 도리보고가 이슈를 찾아온다 |

# 🔎 검색 소스

도리보고가 참고하는 기본 후보 소스는 10곳이다.

### 🌎 글로벌

1. X
2. Threads
3. Reddit
4. GitHub

### 🇰🇷 한국

5. GeekNews
6. OKKY
7. GPTers
8. 디스콰이엇
9. Velog
10. AI Hub

모든 주제에서 10곳을 기계적으로 똑같이 검색하지 않는다.

**이슈와 관련성이 높은 소스를 우선 조사하고, 필요하면 뉴스·논문·공식 문서 등 다른 출처를 추가해 교차검증한다.**

중요한 것은 검색한 사이트의 숫자가 아니라, **서로 다른 곳에서 실제로 같은 이슈가 확인되는지**다.

---

# 🧩 카드의 핵심 구조

도리보고에서 **카드 하나는 서로 다른 이슈 하나**다.

예를 들어 OpenCode Go를 조사한다면:

```text
CARD 01 → 새로운 모델 추가
CARD 02 → 사용량 급증
CARD 03 → 사용량 제한 논쟁
CARD 04 → 특정 오류 발생
CARD 05 → 가격 대비 가치 논쟁
```

같은 내용을 표현만 바꿔 여러 카드로 만들지 않는다.

사용자가 `5개`를 요청했다고 해서 의미 없는 이슈를 억지로 추가하지도 않는다.

---

# 📰 카드 작성 방식

카드는 먼저 **"이게 무슨 이슈인지"를 설명한 다음**, 관련 사이트의 반응을 붙인다.

예시:

```text
## 🟥 CARD 03 — ⚠️ 사용량 제한 논쟁

### "$10인데 생각보다 빨리 제한된다는 말이 나온다"

💡 이게 무슨 이슈야?
OpenCode Go는 여러 AI 모델을 월정액으로 사용할 수 있지만,
원하는 만큼 무제한으로 사용할 수 있는 API와는 다른 구조다.

🔎 무슨 일이 벌어졌어?
일부 사용자가 예상보다 빠르게 사용 한도에 도달했다고 보고하면서,
월 $10 구독으로 실제 어느 정도까지 사용할 수 있는지가 논쟁이 되고 있다.

❓ 왜 중요한데?
AI 코딩 Agent는 한 번의 작업에서도 모델을 여러 번 호출할 수 있어
작업량이 많은 사용자는 일반적인 채팅보다 사용량이 빠르게 늘어날 수 있다.

📌 확인된 사실
일부 사용자의 제한 관련 사례가 확인됐다.

🌐 사이트별 한줄평
- Reddit — 실제 사용량에 따라 한도가 빨리 소진될 수 있다는 경험담.
- GitHub — 사용 한도와 계산 방식에 대한 문제 제기.
- X — 가격은 매력적이지만 많이 사용하는 사람에게 제한이 아쉽다는 반응.

⚠️ 주의할 점
일부 사용자 사례를 근거로 모든 사용자가 빨리 제한된다고 단정하지 않는다.
사용 모델과 작업량에 따라 체감 사용량은 달라질 수 있다.

🔥 신호: 강함
```

### 카드에서 중요한 순서

1. **무슨 이슈인지**
2. **무슨 일이 벌어졌는지**
3. **왜 중요한지**
4. **확인된 사실**
5. **관련 사이트의 한줄평**
6. **주의할 점 / 아직 모르는 부분**
7. 작성자와 원문
8. 신호 강도

이슈 성격에 따라 필요한 설명은 달라질 수 있다. 새 모델 출시라면 모델 변화가 중심이고, 버그라면 어떤 환경에서 문제가 발생했는지가 더 중요할 수 있다.

---

# 💬 사이트별 반응은 한줄평으로

같은 이슈에 대한 여러 사이트의 의견을 길게 반복하지 않는다.

```text
🌐 사이트별 한줄평

- X — 새 모델 추가에 관심이 커지는 분위기.
- Reddit — 모델 자체보다 실제 사용량을 중요하게 보는 반응.
- GitHub — 실제 사용 과정의 문제를 확인하려는 움직임.
- OKKY — 실제 개발에 쓸 만한지가 중요하다는 의견.
```

단, **해당 이슈에 대한 실제 의견을 찾지 못한 사이트는 적지 않는다.**

없는 반응을 만들어서 검색 결과를 풍성하게 보이게 하지 않는다.

가능한 경우 작성자, 핸들/ID, 게시 날짜, 원문 URL을 함께 남긴다.

---

# 🧠 사실과 의견을 분리한다

도리보고는 다음 세 가지를 섞지 않는다.

### 📌 확인된 사실
실제 출처에서 확인할 수 있는 내용.

### 🗣️ 작성자의 주장
X, Reddit, 블로그, 커뮤니티 등의 작성자가 자신의 경험이나 판단으로 말한 내용.

### 🤖 도리보고의 해석
여러 자료를 비교해서 도리보고가 추론한 내용.

특히 사용자 한 명의 경험을 전체 사용자의 상황처럼 확대하지 않는다.

---

# 🔥 이슈 신호 강도

단순히 언급량이 많다고 높은 점수를 주지 않는다.

다음 요소를 함께 본다.

- 최근에 발생한 변화인지
- 서로 다른 출처에서 반복되는지
- 실제 사용 경험이 있는지
- 실제 프로젝트나 구현으로 이어졌는지
- 공식 발표나 1차 자료가 있는지
- 커뮤니티에서 의견이 갈리고 있는지
- 일시적인 사건인지 계속되는 흐름인지

결과는 사람이 빠르게 읽을 수 있도록 직관적인 신호로 표현한다.

```text
🔥 매우 강함
🔥 강함
🔥 보통
🔥 약함
```

# ✍️ 글쓰기 기준

도리보고의 글은 **초보 개발자가 읽어도 바로 이해할 수 있어야 한다.**

전문용어를 없애는 것이 목적은 아니다. 처음 나왔을 때 쉬운 말로 풀어주고, 필요한 경우 그다음에 전문적인 표현을 붙인다.

그리고 저장소의 **`IM_NOT_AI.md`를 글쓰기 1차 기준으로 참고한다.**

따라서:

- 로봇 같은 상투어를 쓰지 않는다.
- 번역투를 피한다.
- 문장 길이를 일정하게 찍어내지 않는다.
- 실제 사람이 설명하듯 자연스럽게 쓴다.
- 어려운 말을 괜히 어렵게 쓰지 않는다.
- 자료를 나열하기보다 읽는 흐름을 만든다.
- 사실과 추정을 분리한다.

`IM_NOT_AI.md` 자체를 도리보고가 수정하거나 대체하지 않는다.

# 💾 데이터 저장 원칙

도리보고는 검색할 때마다 원문 자료를 GitHub에 쌓는 프로젝트가 아니다.

```text
GitHub
 └─ 코드 / 설계 / 규칙

검색 결과
 └─ 기본적으로 대화에서 확인
```

따라서:

- 원문 대량 저장 ❌
- 이미지/스크린샷 대량 저장 ❌
- 검색할 때마다 자료를 GitHub에 누적 ❌
- 필요한 경우에만 장기 보관 검토

GitHub 저장소 용량을 검색 기록으로 불필요하게 소모하지 않는다.

# 🧪 현재 MVP 상태

현재 도리보고는 **자동 수집 서비스가 아니라 조사 방식 검증 단계**다.

현재 핵심은:

```text
ChatGPT 웹 검색
      ↓
여러 출처 조사
      ↓
이슈 분류
      ↓
반응 확인
      ↓
카드뉴스형 텍스트 작성
```

웹/API 자동 수집은 아직 구현하지 않는다.

실제 사용을 반복하면서:

**조사 → 사용 → 부족한 점 발견 → 규칙 보완 → 다시 조사**

순서로 다듬는다.

# 🗺️ 앞으로의 기준

도리보고가 잘 만들어졌다는 기준은 검색 사이트가 많다는 것이 아니다.

**사용자가 결과를 읽고 나서 "그래서 지금 무슨 일이 벌어지고 있는 건데?"라는 질문에 바로 답을 얻을 수 있어야 한다.**

그리고 카드마다 다른 이슈를 보여주면서, 그 이슈를 여러 곳에서 어떻게 바라보는지도 한눈에 알 수 있어야 한다.
