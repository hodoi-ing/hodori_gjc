# 🛰️ 도리보고 개선 메모

> 2026-08-27 — 최신 이슈 탐지 구조 재설계 메모

## 왜 이 메모를 남기나

최근 DRI로 중국 AI 흐름을 조사했을 때 Qwen, Kimi, MiniMax는 찾았지만 Z.ai / Ox Alpha처럼 실제로 크게 움직이고 있던 핵심 이슈를 놓쳤다.

호도리가 직접 `Z.ai도 난리인데?`라고 알려준 뒤에야 발견했다.

이건 단순히 검색어 하나를 추가할 문제가 아니다.
**특정 회사나 주제 이름을 미리 알고 있어야 발견할 수 있는 구조 자체가 문제다.**

도리보고의 목표는 사용자가 아는 뉴스를 확인하는 것이 아니라,
**어떤 분야를 주더라도 그 분야에서 최근 실제로 움직이고 있는 이슈를 스스로 발견하는 것**이어야 한다.

---

## 핵심 방향

기존:

```text
분야 입력
  ↓
관련 검색
  ↓
최신 글 수집
  ↓
이슈 선정
  ↓
카드
```

개선 방향:

```text
분야 입력
  ↓
🌐 생태계 전체 레이더
  ↓
🔥 변화 / 급상승 신호 탐지
  ↓
🧩 서로 다른 신호를 이슈 단위로 클러스터링
  ↓
🔎 공식자료 + 독립출처 교차검증
  ↓
🧠 "지금 무슨 일이 벌어지고 있는가?" 판단
  ↓
🐯 도리보고 카드
```

---

## 1. 검색어보다 '변화'를 찾는다

처음부터 유명 회사나 모델 이름을 나열해서 검색하지 않는다.

예:

```text
X / Threads / Reddit
뉴스 / RSS
GitHub / Releases / Trending
Hugging Face
개발자 커뮤니티
공식 블로그 / 문서
```

각 소스에서 다음과 같은 **변화 신호**를 찾는다.

- 갑자기 등장한 새로운 이름
- 특정 키워드 언급량 급증
- 새 모델 / 제품 / 기능 출시
- 가격 / API / 사용량 변경
- 서비스 장애
- GitHub star / fork / commit / release 급증
- Hugging Face 신규 모델 및 다운로드 급증
- 여러 커뮤니티에서 같은 문제가 반복 등장
- 논쟁이나 사용자 경험이 갑자기 증가
- 기존 방식 자체를 바꾸는 새로운 도구 등장

특히 **도리보고가 아직 이름조차 모르는 대상**을 발견할 수 있어야 한다.

---

## 2. 최신성만 보지 말고 '속도'를 본다

최신 글이라고 무조건 중요한 이슈가 아니다.

중요한 신호:

```text
최근성
+
갑작스러운 증가 속도(Velocity)
+
출처 다양성
+
실제 반응
+
새로움(Novelty)
+
실질적 영향
```

예를 들어 오래된 유명 모델의 일반적인 뉴스보다,
오늘 처음 등장한 정체불명의 프로젝트가 여러 커뮤니티에서 동시에 확산된다면 후자를 먼저 조사할 수 있어야 한다.

---

## 3. 발견한 신호를 '이슈'로 묶는다

서로 다른 게시물을 각각 카드로 만들지 않는다.

예:

```text
Ox Alpha
Z.ai
GLM
코딩 벤치마크
OpenRouter
```

이런 신호가 발견되면 각각 별개 뉴스로 끝내지 않고,
**같은 사건에서 파생된 신호인지 먼저 조사한다.**

즉 도리보고는 검색 결과 목록이 아니라 **이슈 클러스터**를 만들어야 한다.

```text
여러 게시물
  ↓
신호 추출
  ↓
유사 사건 / 인과관계 / 시간적 연관성 확인
  ↓
하나의 이슈 클러스터
```

---

## 4. 마지막에 깊게 조사한다

레이더에서 발견한 후보를 바로 카드로 만들지 않는다.

각 후보에 대해:

```text
원자료 확인
↓
공식 발표 확인
↓
독립적인 다른 출처 확인
↓
커뮤니티 실제 반응 확인
↓
주장 / 사실 / 추정 분리
↓
왜 지금 중요한지 판단
```

그 뒤에야 카드 생성.

---

## 5. DRI의 목표를 바꾼다

기존 목표:

> 오늘 AI 관련 최신 글 5개 찾기

개선 목표:

> **오늘 이 분야에서 평소와 다르게 움직이고 있는 사건을 찾아내고, 그중 실제로 중요한 이슈를 설명하기**

따라서 `5개`를 억지로 채우지 않는다.

중요한 이슈가 2개면 2개만 보여준다.

반대로 후보가 많으면 신호 강도와 영향도를 기준으로 우선순위를 정한다.

---

## 6. 분야가 무엇이든 작동해야 한다

AI에만 맞춘 구조를 만들지 않는다.

예:

```text
DRI
분야: 자동차
```

라면 자동차 생태계에서 최근 움직이는 신호를 찾는다.

```text
DRI
분야: 삼성전자
```

라면 삼성전자와 관련해 최근 평소와 다르게 움직이는 사건을 찾는다.

핵심은 특정 분야의 회사 목록을 미리 하드코딩하는 것이 아니라,
**분야가 바뀌어도 '변화 탐지 → 클러스터링 → 검증' 구조가 유지되는 것**이다.

---

## 7. 이번 메모에서 당장 코드를 크게 바꾸지는 않는다

현재 도리보고는 조사 방식과 결과 형식을 검증하는 MVP 단계다.

따라서 이 문서는 **향후 개선 방향을 기록하는 설계 메모**다.

구현 전에 먼저 실제 조사 실험을 여러 번 수행하면서:

- 어떤 소스가 어떤 신호를 잘 잡는지
- 어떤 신호가 실제 이슈로 이어지는지
- 중복 이슈를 어떻게 묶는 게 좋은지
- 최신성과 중요도를 어떻게 구분할지
- 검색 도구의 한계를 어디서 보완할지

를 검증한다.

---

## 한 문장

> **도리보고는 '최신 뉴스를 검색하는 도구'가 아니라, 어떤 분야에서든 '지금 평소와 다르게 움직이는 것'을 먼저 발견하는 레이더가 되어야 한다.**
