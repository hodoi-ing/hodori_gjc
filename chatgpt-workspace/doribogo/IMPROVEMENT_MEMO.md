# 🛰️ 도리보고 개선 메모

> 2026-08-27 — 최신 뉴스·이슈 자율 발견 구조 재설계 메모

## 🚨 최상위 원칙

**도리보고는 최신 뉴스와 이슈를 스스로 발견해야 한다.**

사용자가 특정 회사·모델·프로젝트의 이름을 알려줘야 발견할 수 있다면 DRI의 목적을 달성하지 못한 것이다.

사용자가

```text
DRI
분야: AI
```

라고만 입력해도 도리보고가 스스로 해당 분야의 정보 생태계를 탐색하고,
**최근 발생했거나 갑자기 커지고 있는 사건을 발견하여 이슈로 만들어야 한다.**

예를 들어 사용자가 `Z.ai`라는 이름을 전혀 말하지 않았더라도,
Z.ai / Ox Alpha처럼 최근 급격하게 주목받는 사건이 여러 신호에서 나타난다면 도리보고가 먼저 발견해야 한다.

따라서 DRI는 **검색 시스템이 아니라 자율적인 최신 이슈 발견 시스템**을 지향한다.

---

## 왜 이 메모를 남기나

최근 DRI로 중국 AI 흐름을 조사했을 때 Qwen, Kimi, MiniMax는 찾았지만 Z.ai / Ox Alpha처럼 실제로 크게 움직이고 있던 핵심 이슈를 놓쳤다.

호도리가 직접 `Z.ai도 난리인데?`라고 알려준 뒤에야 발견했다.

이건 단순히 검색어 하나를 추가할 문제가 아니다.
**특정 회사나 주제 이름을 미리 알고 있어야 발견할 수 있는 구조 자체가 문제다.**

도리보고의 목표는 사용자가 아는 뉴스를 확인하는 것이 아니라,
**어떤 분야를 주더라도 그 분야에서 최근 실제로 움직이는 뉴스와 이슈를 스스로 발견하는 것**이어야 한다.

---

## 📰 '최신 뉴스'와 '최신 이슈'를 구분한다

### 최신 뉴스

개별적으로 새로 올라온 기사·게시물·발표.

### 최신 이슈

여러 정보에서 관측된 변화가 서로 연결되면서,
**지금 실제로 중요하게 움직이고 있다고 판단되는 사건 또는 흐름.**

따라서 목표는:

```text
❌ 최신 기사 5개 가져오기

⭕ 최근에 새롭게 발생했거나 급격하게 커지는 이슈를 스스로 발견하기
```

뉴스는 **관측값**이고, 이슈는 여러 관측값을 연결한 **판단 결과**다.

---

## 🔭 핵심 탐색 구조

기존:

```text
분야 입력
  ↓
관련 검색
  ↓
최신 글 수집
  ↓
이슈 선정
  ↓
카드
```

개선 방향:

```text
분야 입력
  ↓
🌐 생태계 전체 탐색
  ↓
🛰️ 변화 신호 수집
  ↓
🔥 급상승 / 신규 / 이상징후 탐지
  ↓
🧩 신호를 이슈 단위로 클러스터링
  ↓
🔎 공식자료 + 독립출처 교차검증
  ↓
🧠 "지금 무슨 일이 벌어지고 있는가?" 판단
  ↓
📈 중요도 / 최신성 / 확산속도 평가
  ↓
🐯 도리보고 카드
```

---

## 1. 검색어보다 '변화'를 찾는다

처음부터 유명 회사나 모델 이름을 나열해서 검색하지 않는다.

도리보고가 아직 이름을 모르는 대상도 발견할 수 있어야 한다.

### 탐색 후보

```text
뉴스 / RSS
공식 블로그 / 문서
X / Threads / Reddit
개발자 커뮤니티
GitHub / Releases / Trending
Hugging Face
논문 / 연구 발표
제품·가격·API 변경 정보
```

각 소스에서 다음과 같은 **변화 신호**를 찾는다.

- 갑자기 등장한 새로운 이름
- 특정 키워드 언급량 급증
- 새 모델 / 제품 / 기능 출시
- 가격 / API / 사용량 변경
- 서비스 장애
- GitHub star / fork / commit / release 급증
- Hugging Face 신규 모델 및 다운로드 급증
- 여러 커뮤니티에서 같은 문제가 반복 등장
- 논쟁이나 사용자 경험이 갑자기 증가
- 기존 방식 자체를 바꾸는 새로운 도구 등장

**핵심: 대상의 이름을 검색하는 것이 아니라, 대상이 남기는 변화 신호를 찾는다.**

---

## 2. '최신성'보다 변화 속도를 본다

최신 글이라고 무조건 중요한 이슈는 아니다.

다음 신호를 함께 본다.

```text
최근성
+
갑작스러운 증가 속도(Velocity)
+
새로움(Novelty)
+
출처 다양성
+
실제 반응
+
실질적 영향
```

예를 들어 오래된 유명 모델의 일반적인 뉴스보다,
오늘 처음 등장한 정체불명의 프로젝트가 여러 커뮤니티에서 동시에 확산된다면 후자를 먼저 조사할 수 있어야 한다.

---

## 3. 발견한 신호를 '이슈'로 묶는다

서로 다른 게시물을 각각 카드로 만들지 않는다.

예:

```text
Ox Alpha
Z.ai
GLM
코딩 벤치마크
OpenRouter
```

이런 신호가 발견되면 각각 별개 뉴스로 끝내지 않고,
**같은 사건에서 파생된 신호인지 먼저 조사한다.**

즉 도리보고는 검색 결과 목록이 아니라 **이슈 클러스터**를 만들어야 한다.

```text
여러 게시물
  ↓
신호 추출
  ↓
유사 사건 / 인과관계 / 시간적 연관성 확인
  ↓
하나의 이슈 클러스터
```

---

## 4. 이슈 발견은 '발견 → 검증 → 해석' 순서로 한다

레이더에서 발견한 후보를 바로 카드로 만들지 않는다.

```text
① 발견
최근 움직임이 큰 후보를 넓게 찾는다.

② 검증
원자료 → 공식자료 → 독립출처 → 실제 사용자 반응을 확인한다.

③ 해석
서로 연결되는 사건인지 판단하고,
왜 지금 중요한지 설명한다.
```

검증 과정에서 **사실 / 주장 / 추정 / 커뮤니티 반응**을 구분한다.

---

## 5. DRI의 성공 기준을 바꾼다

기존:

> 오늘 AI 관련 최신 글 5개 찾기

개선:

> **오늘 이 분야에서 새롭게 발생했거나 평소와 다르게 움직이고 있는 사건을 스스로 발견하고, 그중 실제로 중요한 최신 이슈를 설명하기**

따라서 `5개`를 억지로 채우지 않는다.

중요한 이슈가 2개면 2개만 보여준다.

후보가 많으면 신호 강도·확산속도·영향도·출처 다양성 등을 기준으로 우선순위를 정한다.

**카드 개수보다 발견 정확도가 우선이다.**

---

## 6. 분야가 무엇이든 작동해야 한다

AI에만 맞춘 구조를 만들지 않는다.

예:

```text
DRI
분야: 자동차
```

라면 자동차 생태계에서 최근 움직이는 신호를 찾는다.

```text
DRI
분야: 삼성전자
```

라면 삼성전자와 관련해 최근 평소와 다르게 움직이는 사건을 찾는다.

핵심은 특정 분야의 회사 목록을 미리 하드코딩하는 것이 아니라,
**분야가 바뀌어도 '탐색 → 변화 탐지 → 클러스터링 → 검증 → 이슈 판단' 구조가 유지되는 것**이다.

---

## 7. '내가 아는 이름'을 입력받지 않아도 발견되어야 한다

이 항목은 향후 구현 시 반드시 테스트 케이스로 사용한다.

예:

```text
사용자 입력:
DRI / 분야: AI

사용자는 Z.ai를 언급하지 않음.

기대 결과:
도리보고가 최근 Z.ai 관련 신호를 스스로 발견하고,
다른 관련 신호와 연결한 뒤 이슈 후보로 제시할 수 있어야 함.
```

같은 방식으로 앞으로 알려지지 않은 신규 회사·프로젝트·모델도 테스트한다.

**특정 이름을 힌트로 넣었을 때만 찾는 것은 발견 성공으로 인정하지 않는다.**

---

## 8. 검색 도구 자체의 한계를 고려한다

'스스로 발견한다'는 것은 무작정 검색 한 번으로 해결되는 문제가 아니다.

검색엔진은 보통 사용자가 지정한 질의와 관련된 결과를 찾는 데 강하지만,
인터넷 전체에서 새롭게 발생하는 이상징후를 지속적으로 감시하는 시스템은 아니다.

따라서 향후 구현에서는 필요에 따라:

```text
다중 소스 탐색
+
시간 범위별 비교
+
검색어 자동 확장
+
새로운 엔티티 추출
+
신호 간 관계 분석
+
반복 탐색
```

등을 실험해야 한다.

최종적으로는 **한 번의 검색 결과에 종속되지 않는 발견 구조**를 만드는 것이 목표다.

---

## 9. 이번 메모에서 당장 코드를 크게 바꾸지는 않는다

현재 도리보고는 조사 방식과 결과 형식을 검증하는 MVP 단계다.

따라서 이 문서는 **향후 개선 방향을 기록하는 설계 메모**다.

구현 전에 실제 조사 실험을 여러 번 수행하면서:

- 어떤 소스가 어떤 변화 신호를 잘 잡는지
- 이름을 모르는 신규 대상을 얼마나 발견할 수 있는지
- 어떤 신호가 실제 이슈로 이어지는지
- 중복 이슈를 어떻게 묶는 게 좋은지
- 최신성과 중요도를 어떻게 구분할지
- 검색 도구의 한계를 어디서 보완할지
- 발견 실패를 어떻게 측정할지

를 검증한다.

YES가 아니라면 아직 자율 발견 시스템이라고 보기 어렵다.

## 한 문장

> **도리보고는 '최신 뉴스를 검색하는 도구'가 아니라, 사용자가 이름을 알려주지 않아도 어떤 분야에서든 최근 발생하거나 급격히 커지는 변화를 스스로 발견하고, 그것을 검증된 최신 이슈로 만들어내는 탐색 시스템이어야 한다.**
