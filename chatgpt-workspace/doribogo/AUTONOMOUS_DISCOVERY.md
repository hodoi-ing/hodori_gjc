# 🧭 도리보고 자율탐색

> 도리보고는 개인화된 추천기가 아니라 **범용 정보탐색 엔진**을 지향한다.
>
> **검색하지 말고, 조사한다.**

## 목적

도리보고가 미리 정해진 검색 목록을 많이 훑는 것에서 끝나지 않도록 한다.

핵심은 다음 루프다.

```text
질문
 ↓
질문의 본질 파악
 ↓
탐색 전략 수립
 ↓
1차 탐색
 ↓
새로운 대상/키워드 발견
 ↓
추가 탐색 후보 생성
 ↓
우선순위 판단
 ↓
추가 탐색
 ↓
교차검증 / 반대 증거 탐색
 ↓
탐색 방향 재평가
 ↓
충분한가?
 ├─ NO → 다시 탐색
 └─ YES → 최종 결과
```

## 핵심 원칙

### 1. 발견은 다음 탐색의 씨앗이다

초기 검색 소스는 시작점(seed)일 뿐이다. 검색 결과에서 프로젝트·인물·키워드·논쟁·문서·사건 등이 발견되면 새로운 탐색 후보가 될 수 있다.

### 2. 탐색 경로는 고정하지 않는다

GitHub, Threads, Reddit, 뉴스, 공식 문서 등은 기본 출발점이다. 질문과 발견된 대상의 성격에 따라 정보원을 추가하거나 제외할 수 있다.

### 3. 발견과 사실을 구분한다

검색 결과에서 발견한 주장은 사실로 확정하지 않는다. 원문, 공식 문서, 릴리스, 커밋, 독립 출처 등 적절한 근거를 통해 검증한다.

결과는 가능하면 다음처럼 구분한다.

- 확인된 사실
- 신뢰할 수 있는 주장
- 커뮤니티 의견
- 미확인 주장
- 서로 충돌하는 정보

### 4. 자기 검색 결과도 의심한다

중요한 주장에는 독립 출처와 반대 증거를 확인한다.

```text
주장 발견
 ↓
근거 확인
 ↓
독립 출처 확인
 ↓
반대 증거 탐색
 ↓
신뢰도 재평가
```

### 5. 무한 탐색하지 않는다

발견된 모든 가지를 따라가면 비용이 폭증한다. 후보의 탐색 가치와 깊이, 예상 정보 증가량을 이용해 가지치기한다.

**개인 관련성은 사용하지 않는다.** 도리보고의 사용 상황을 특정하지 않고 범용 Research Engine으로 유지한다.

### 6. 종료도 자율 판단한다

검색 결과의 개수가 아니라 조사 품질을 기준으로 종료한다. 핵심 질문에 답할 수 있고 핵심 사실이 충분히 검증되며, 추가 탐색의 기대 정보량이 낮으면 멈춘다.

## 탐색 상태

```text
DiscoveryState
├─ goal                 # 이번 조사가 답하려는 질문
├─ seeds                # 초기 탐색 출발점
├─ frontier             # 아직 조사하지 않은 후보
├─ visited              # 이미 조사한 후보
├─ evidence             # 확인된 근거
├─ depth                # 탐색 깊이
└─ budget               # 추가 탐색 예산
```

## 후보 우선순위

후보는 최소한 다음 요소를 고려한다.

```text
relevance
+ novelty
+ verification
+ information_gain
```

여기서 `information_gain`은 사용자 개인에게 유용한 정도가 아니라 **추가 조사했을 때 현재 조사에 더해질 것으로 예상되는 정보량**이다.

`personal_value`나 개인 프로필 기반 점수는 사용하지 않는다.

## 탐색 경로 기록

가능하면 다음 흐름을 기록한다.

```text
발견 대상
→ 발견 출처
→ 추가 조사 이유
→ 실제 조사 결과
→ 새로 발견한 대상
→ 다음 탐색 결정
→ 계속/종료 이유
```

최종 결과만 남기는 것이 아니라 **왜 그 탐색 경로를 선택했는지** 추적 가능해야 한다.

## DRI의 역할

DRI는 최종 목적지가 아니라 **자율탐색 엔진의 첫 번째 테스트베드**다.

예:

```text
사용자: 오늘 AI 개발 쪽에서 중요한 변화 찾아봐.

DRI
 ↓
GitHub에서 OMP2 발견
 ↓
"단순 업데이트인가, 구조적 변화인가?"
 ↓
OMP2 원문 / release / commit 조사
 ↓
기존 OMP/Pi와의 관계 발견
 ↓
관련 커뮤니티 반응 조사
 ↓
핵심 사실 교차검증
 ↓
왜 중요한지 설명
 ↓
탐색 종료
 ↓
DRI 카드 생성
```

## 범용 엔진으로 유지

동일한 자율탐색 계층을 여러 조사 유형에서 사용할 수 있어야 한다.

```text
자율탐색 엔진
 ├─ DRI: AI 생태계 탐색
 ├─ DRT: 특정 주제 심층조사
 ├─ GitHub Research
 ├─ News Research
 ├─ Product Research
 └─ General Research
```

DRI가 AI 뉴스에 특화되는 것은 괜찮지만 **자율탐색 로직 자체는 특정 도메인에 종속시키지 않는다.**

## 단계적 구현

### Phase 1 — 탐색 판단

- 후보 생성
- 우선순위 평가
- 탐색 깊이 제한
- 종료 조건
- 탐색 이유 기록

### Phase 2 — 실제 탐색 연결

- 웹 검색 결과를 frontier에 연결
- 발견 결과를 다음 후보로 자동 등록
- 후보별 추가 검색 수행

### Phase 3 — 적응형 탐색

- 질문 유형에 따른 정보원 선택
- 검색 결과에 따른 검색어 재작성
- 탐색 방향 전환
- 가지치기

### Phase 4 — 검증 루프

- 출처 독립성 확인
- 반대 증거 탐색
- 주장과 사실 분리
- 신뢰도 평가

### Phase 5 — 자율 종료

- 정보 증가량 측정
- 핵심 질문 해결도 평가
- 추가 조사 가치 평가
- 충분한 근거 확보 시 종료

## 범위 밖

도리보고 자율탐색 엔진은 현재 다음을 목표로 하지 않는다.

- 사용자 개인 성향 기반 우선순위
- 개인 Ontology 기반 추천
- 사용자의 장기 목표 추론
- 사용자를 대신한 무단 행동
- 무제한 재귀 탐색
- MCP/OMP2 직접 결합

이 영역은 필요할 경우 별도의 상위 시스템 또는 실행 계층에서 다룬다.
