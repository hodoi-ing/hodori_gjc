# 🧭 DRI 자율탐색 실험

> DRI(Dori + Issue)를 도리보고의 첫 번째 자율 정보탐색 테스트베드로 사용한다.

## 목적

DRI가 미리 정해진 검색 목록을 순서대로 훑는 데서 끝나지 않고, **탐색 중 발견한 대상이 새로운 탐색 후보가 되도록** 만든다.

핵심은 검색량을 늘리는 것이 아니라 다음 루프를 검증하는 것이다.

```text
탐색 목표
  ↓
1차 탐색
  ↓
이슈/대상 발견
  ↓
새로운 탐색 후보 생성
  ↓
후보 우선순위 판단
  ↓
추가 탐색
  ↓
충분한 정보인가?
  ├─ 아니오 → 다시 탐색
  └─ 예     → 카드 생성
```

## 이번 실험의 범위

처음부터 웹 크롤러나 완전 자율 Agent를 만들지 않는다.

### 포함

- DRI의 기본 탐색 소스는 **시작점(seed)** 으로만 취급한다.
- 조사 결과에서 발견된 프로젝트·인물·키워드·논쟁·문서 등을 **discovery candidate**로 만든다.
- 후보마다 `왜 추가 조사할 가치가 있는지`를 기록한다.
- 탐색 깊이와 후보 수에 상한을 둔다.
- 정보 증가량이 낮아지면 추가 탐색을 중단한다.
- 최종 결과에는 `어디서 발견되어 어떤 경로로 조사 범위가 확장됐는지`를 남긴다.

### 제외

- 기존 DRI 카드 포맷 전면 개편
- 검색 제공자 교체
- MCP/OMP2 직접 통합
- 자동 발행
- ONTOLOGY 자동 수정
- 무제한 재귀 탐색

## 탐색 상태 모델

```text
DiscoveryState
├─ goal                 # 이번 DRI가 답하려는 질문
├─ seeds                # 사람이 정한 초기 탐색 출발점
├─ frontier             # 아직 조사하지 않은 후보
├─ visited              # 이미 조사한 후보
├─ evidence             # 확인된 근거
├─ depth                # 탐색 깊이
└─ budget               # 추가 탐색 예산
```

## 후보 생성 규칙

발견된 항목을 모두 따라가지 않는다.

후보는 다음 조건을 함께 본다.

```text
관련성
+ 새 정보 가능성
+ 현재 이슈와의 연결성
+ 독립적인 검증 가능성
+ 호도리에게 실질적인 의미
```

예를 들어 DRI가 `OMP2`를 발견했다면:

```text
OMP2
 ↓
Rust rewrite 발견
 ↓
기존 OMP와의 관계가 중요하다고 판단
 ↓
OMP2 README / release / commit 추가 조사
 ↓
Pi와의 관계 발견
 ↓
Pi를 추가 탐색 후보로 등록
```

반대로 단순히 README에 언급된 무관한 라이브러리까지 따라가지는 않는다.

## 탐색 종료 조건

다음 중 하나가 충족되면 추가 탐색을 줄이거나 종료한다.

1. 요청한 핵심 질문에 답할 수 있다.
2. 새로운 후보의 예상 정보 가치가 낮다.
3. 독립적인 출처에서 핵심 사실이 충분히 교차검증됐다.
4. 탐색 깊이 또는 후보 예산에 도달했다.
5. 새 탐색이 기존 결과를 반복한다.

**카드 개수를 채우기 위해 탐색을 계속하지 않는다.**

## 첫 번째 성공 기준

아래 예시가 실제 조사에서 재현되면 1차 실험 성공으로 본다.

```text
사용자: 오늘 AI 개발 쪽에서 중요한 변화 찾아봐.

DRI
 ↓
GitHub에서 OMP2 발견
 ↓
"단순 업데이트가 아니라 Rust rewrite인가?"라는 추가 질문 생성
 ↓
OMP2 원문 조사
 ↓
기존 OMP/Pi와의 관계 발견
 ↓
관련 커뮤니티 반응 추가 조사
 ↓
핵심 사실 교차검증
 ↓
"이 변화가 왜 중요한가"를 설명할 수 있음
 ↓
탐색 종료
 ↓
DRI 카드 생성
```

## 구현 원칙

1. **기존 DRI를 깨지 않는다.** 자율탐색은 별도 실험 계층으로 붙인다.
2. **LLM은 후보 생성·판단을 담당하고, 결정 가능한 제약은 코드가 담당한다.**
3. **검색 결과와 AI의 추론을 분리한다.** 발견 사실과 `추가 조사할 이유`를 같은 필드에 섞지 않는다.
4. **탐색 경로를 기록한다.** 나중에 왜 해당 이슈가 카드가 되었는지 재현할 수 있어야 한다.
5. **ONTOLOGY는 읽기만 한다.** 이 실험이 ONTOLOGY를 자동 수정하지 않는다.
6. **MVP에서는 작은 탐색 예산으로 시작한다.** 성능보다 탐색 품질을 먼저 검증한다.
