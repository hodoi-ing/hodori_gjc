# 🐯 도리보고의 장기 목적

> 도리보고는 단순한 뉴스 검색기가 아니다.

도리보고를 만드는 최종 목적은 **인터넷 곳곳의 이슈와 사람들의 반응을 지속적으로 찾아보고, 필요한 정보를 선별·검증해서 나중에 자동화 시스템의 입력으로 활용하는 것**이다.

현재는 사람이 ChatGPT에게 검색을 요청하고 카드 형태로 결과를 확인하는 MVP 단계지만, 장기적으로는 다음 흐름으로 발전시킨다.

```text
🌐 웹 / 뉴스 / SNS / 커뮤니티 / GitHub
                 ↓
              🔎 수집
                 ↓
            🎯 관심 신호
                 ↓
             🧠 이슈 선별
                 ↓
             💬 반응 확인
                 ↓
             🔗 교차검증
                 ↓
          📰 도리보고 카드
                 ↓
          📦 구조화된 정보
                 ↓
       ┌─────────┴─────────┐
       ↓                   ↓
    📝 블로그           🤖 자동화
    초안/콘텐츠          다른 워크플로
```

## 왜 먼저 검색 품질을 만드는가?

자동 블로그 작성부터 시작하면 검색 결과가 부정확하거나 관심 없는 정보까지 그대로 콘텐츠가 될 수 있다.

그래서 도리보고는 먼저 다음을 잘하는 것을 목표로 한다.

- 무엇이 새롭게 바뀌었는지 찾기
- 사람들이 실제로 관심을 보이는지 확인하기
- 같은 이슈가 여러 출처에서 확인되는지 비교하기
- 접근할 수 없는 원문이 있으면 공개된 다른 출처로 교차검증하기
- 사실과 사람들의 주장·반응을 구분하기
- 단순한 뉴스와 실제로 콘텐츠 가치가 있는 이슈를 구분하기
- GitHub에서 새롭게 뜨는 프로젝트와 개발 흐름을 발견하기

## 📡 레이더의 역할

`RADAR.md`에 등록된 관심 계정·사이트·GitHub 프로젝트·키워드는 향후 자동화에서 **우선 감시할 정보원**이 된다.

단, 레이더만 보는 폐쇄적인 구조로 만들지 않는다.

```text
⭐ 레이더 우선 확인
        ↓
🔎 일반 검색으로 범위 확장
        ↓
🐙 GitHub / 전문 사이트 확인
        ↓
💬 주변 반응 확인
        ↓
🔗 교차검증
```

레이더에 없는 새로운 정보원이 발견되면 가치가 있다고 판단되는 경우 레이더 후보로도 남길 수 있다.

## 🧱 자동화할 때 지켜야 할 방향

도리보고의 목표는 **많이 모으는 것**이 아니라 **쓸 만한 정보를 골라내는 것**이다.

```text
1000개 수집
   ↓
100개 관련 자료
   ↓
20개 관심 신호
   ↓
7개 이슈 후보
   ↓
3개 콘텐츠 가치가 높은 이슈
   ↓
1개 또는 몇 개의 실제 콘텐츠 소재
```

따라서 나중에 자동화할 때도 원문 전체와 이미지를 무작정 GitHub에 저장하지 않는다. 필요한 메타데이터, 요약, 출처, 작성자, 원문 링크, 이슈 판단 근거처럼 **다음 단계에서 다시 사용할 수 있는 구조화된 정보**를 중심으로 관리한다.

## 📝 나중에 연결할 수 있는 활용처

도리보고가 충분히 안정되면 다음과 연결할 수 있다.

- 블로그 글감 자동 발견
- 블로그 초안 생성용 자료 묶음 만들기
- SNS 콘텐츠 소재 발견
- 관심 분야 주간/일간 브리핑
- 새로운 GitHub 프로젝트 발견 알림
- 특정 계정·키워드·분야의 반응 변화 추적
- 다른 AI 에이전트나 자동화 워크플로의 검색 입력 제공

**중요:** 자동 게시가 목적은 아니다. 도리보고는 먼저 **좋은 정보를 발견하고 판단할 수 있는 정보 레이어**가 되는 것을 목표로 한다. 실제 게시나 외부 공개는 별도의 검토·승인 단계를 두는 것을 기본으로 한다.

## 🐯 한 문장으로 기억하기

**도리보고 = 인터넷을 요리조리 살펴보고, 사람들이 관심 가질 만한 이슈와 반응을 찾아서 나중에 자동화에 쓸 수 있는 정보로 만들어주는 레이어.**
