# 🐯 도리보고 RADAR

도리보고가 이슈를 찾을 때 **항상 먼저 확인할 관심 정보원**을 관리하는 목록이다.

레이더는 검색 범위를 좁히기 위한 목록이 아니라, **놓치면 아쉬운 정보원을 우선 확인하기 위한 출발점**이다.

## 🎯 기본 원칙

1. 레이더 소스를 먼저 확인한다.
2. 레이더에 없는 새로운 출처도 검색한다.
3. 특정 사이트가 막혀 있으면 접근을 우회하려 하지 않고 공개 검색 결과, 공식 API, RSS, 캐시 가능한 공개 자료, 다른 출처의 인용 등으로 최대한 교차확인한다.
4. 원문을 확인하지 못한 내용은 사실처럼 단정하지 않는다.
5. 실제 게시물의 작성자·날짜·원문을 확인할 수 있으면 함께 기록한다.
6. 로그인·유료벽·비공개 영역을 무단으로 우회하지 않는다.

## 🔎 최대한 가져오는 검색 전략

도리보고는 하나의 사이트에서 모든 정보를 가져오려고 하지 않는다.

```text
관심 계정/사이트 확인
        ↓
검색엔진으로 제목·작성자·핵심 문구 검색
        ↓
원문 URL 후보 탐색
        ↓
공개 페이지 / 공식 API / RSS 확인
        ↓ 실패
다른 공개 출처에서 동일 내용 교차확인
        ↓
작성자·날짜·내용 검증
        ↓
카드에 반영
```

특히 Threads·X처럼 검색엔진에 모든 게시물이 즉시 색인되지 않는 서비스는 **계정명 + 핵심 문구 + 주제 + 기간**을 조합해 찾는다.

## 🐙 GitHub 레이더

DRI를 실행할 때는 일반 이슈와 별도로 GitHub에서도 최소 한 번은 새 프로젝트나 최근 움직임을 확인한다.

우선순위:

1. 최근 급상승
2. 최근 Release
3. 최근 커밋 활성도
4. Issues / PR에서 나타나는 실제 문제
5. 커뮤니티 언급
6. 직접 써볼 가치

## ⚠️ 접근 제한 처리

접근이 막힌 사이트를 무리하게 뚫는 것이 목적이 아니다.

```text
원문 접근 가능 → 원문 확인
원문 접근 불가 → 공개 검색 결과 확인
                  ↓
              다른 출처 교차확인
                  ↓
       확인 가능한 범위만 카드 작성
```

출처가 충분하지 않으면 **“확인 불가”라고 표시하고 억지로 카드를 만들지 않는다.**

## 🧭 레이더의 역할

레이더는 DRT/DRI 모두에서 사용할 수 있다.

- **DRT:** 사용자가 준 주제와 관련된 레이더 소스를 우선 확인
- **DRI:** 레이더에서 먼저 신호를 찾은 뒤 일반 웹·뉴스·GitHub까지 확장

레이더는 계속 추가할 수 있지만, 등록된 소스만 검색하는 폐쇄형 목록으로 만들지 않는다.
