# 🔎 도리보고 검색 구조

도리보고의 검색 범위를 **AI 전용 → 분야와 주제에 따라 바뀌는 범용 이슈 탐색**으로 확장한다.

핵심은 사이트 10곳을 항상 똑같이 검색하는 것이 아니다.

> **주제 → 분야 판단 → 적합한 검색 소스 선택 → 이슈 후보 수집 → 교차검증 → 카드 생성**

---

## 1. DRT / DRI 검색 방식

### DRT — 주제가 있는 검색
사용자가 주제를 지정한다.

### DRI — 주제를 발견하는 검색
사용자가 분야만 지정하거나 전체로 요청한다.

---

## 2. 분야별 검색 소스

고정된 사이트를 모든 주제에 적용하지 않는다. 주제에 따라 뉴스·전문 사이트·커뮤니티·SNS·공식 자료·GitHub 등 적합한 소스를 선택한다.

---

## 3. 검색 엔진을 기본 입구로 사용

검색엔진은 특정 사이트에 직접 들어가는 것보다 **관련 자료가 어디에 있는지 발견하는 역할**을 한다.

```text
검색엔진
   ↓
관련 페이지 후보
   ↓
사이트/분야 분류
   ↓
원문 확인
   ↓
이슈 후보 생성
```

검색 결과가 특정 사이트에 막혀 있어도 검색을 중단하지 않는다. 검색 결과의 제목·요약으로 후보를 파악하고, 같은 내용을 공개된 다른 출처에서 확인하며, 공식 문서나 원자료가 있으면 우선한다.

---

## 4. GitHub는 별도 검색 레이어

AI·개발 분야에서는 GitHub를 일반 웹 결과와 별도로 확인한다.

```text
웹 검색
   ├─ 뉴스
   ├─ 블로그
   ├─ 커뮤니티
   └─ SNS

GitHub 검색
   ├─ Repository
   ├─ Releases
   ├─ Issues / PR
   ├─ 최근 커밋
   └─ 코드 / README
```

---

## 5. GPTaku Codex 검색·접근 전략

도리보고는 Claude Code용 원본 `gptaku_plugins`가 아니라 **Codex용 `fivetaku/gptaku-plugins-codex`**를 기준으로 한다.

여기서 가져올 것은 플러그인 이름 자체보다 **두 가지 전략**이다.

### 🔎 insane-search-codex — 접근 전략

검색으로 후보 URL을 찾은 뒤, 일반 접근이 실패하면 공개적으로 허용되는 다른 접근 경로를 단계적으로 시도한다. 공개 자료를 읽는 것이 목적이며 로그인·유료벽·인증을 우회하지 않는다. 실제 `insane-search`의 공개 사용 범위도 공개 콘텐츠이며, 인증/유료벽에서는 중단하도록 명시되어 있다. citeturn0search1

```text
후보 URL 발견
   ↓
일반 접근
   ↓ 실패
공개 API / RSS / 기타 공개 경로
   ↓ 실패
허용되는 브라우저 접근
   ↓ 실패
다른 공개 출처로 교차검증
```

### 🧠 insane-research-codex — 조사 전략

검색 결과를 그대로 믿지 않고 **질문을 쪼개고 → 여러 출처를 비교하고 → 원자료를 확인하고 → 주장과 근거를 분리하는 방식**을 도리보고 조사 과정에 적용한다.

즉 도리보고는 다음 두 전략을 결합한다.

> **insane-search-codex = 최대한 자료를 확보하는 방법**
>
> **insane-research-codex = 확보한 자료를 제대로 검증하는 방법**

Codex용 플러그인 저장소에는 `insane-search` hardening 동기화 작업도 존재하므로, 실제 설치 시에는 저장소의 최신 상태를 기준으로 확인한다. citeturn0search0

---

## 6. ChatGPT에서의 동일 전략

도리보고를 여기서 테스트할 때도 **현재 ChatGPT의 웹 검색을 중심으로 위 두 전략을 최대한 재현한다.** 별도의 Codex 플러그인이 이 ChatGPT 세션에 직접 설치되어 있다고 가장하지 않는다.

```text
🐯 도리보고
      ↓
DRT / DRI
      ↓
🌐 Web Search로 후보 발견
      ↓
📄 원문 확인
      ↓ 실패
🔎 다른 공개 검색 결과 / 공개 경로 탐색
      ↓
🐙 GitHub 별도 확인
      ↓
🧠 여러 출처 교차검증
      ↓
💬 주변 반응 확인
      ↓
📰 카드 생성
```

따라서 **현재 ChatGPT에서의 도리보고 검색 결과도 Codex용 GPTaku의 전략을 최대한 따라가되, 실제 `insane-search-codex` 플러그인을 실행한 결과라고 표현하지 않는다.**

---

## 7. 접근 제한 원칙

도리보고는 로그인·유료벽·비공개 자료를 뚫는 것을 목표로 하지 않는다.

```text
공개 자료
  ↓
일반 접근
  ↓ 실패
공개 API / RSS / 공개 데이터
  ↓ 실패
허용되는 브라우저 접근
  ↓ 실패
다른 공개 출처로 교차검증
```

로그인이나 인증이 필요한 콘텐츠는 접근 불가로 표시하고 다른 출처를 찾는다. 자동 요청은 해당 사이트의 이용약관·robots.txt·rate limit 등 허용 범위를 준수한다. citeturn0search1

## 8. 도리보고의 전체 검색 레이어

```text
                    🐯 도리보고
                         │
                  DRT / DRI 요청
                         │
                🔎 검색 오케스트레이션
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
       🌐 웹 검색      🐙 GitHub      🧰 GPTaku 전략
          │              │          search + research
          │              │              │
          └──────────────┼──────────────┘
                         ↓
                    이슈 후보화
                         ↓
                     교차검증
                         ↓
                     반응 확인
                         ↓
                     카드 생성
```

**중요:** 여기서 `검색 오케스트레이션`은 현재 도리보고에 완성된 실행 프로그램이 있다는 뜻이 아니다. **앞으로 구현할 검색 흐름의 설계**이며, 현재 ChatGPT에서는 위 전략을 수동으로 최대한 재현한다.

---

## 9. 최종 이슈 선정

검색 결과를 그대로 카드로 만들지 않는다.

```text
최근성
+ 실제 변화
+ 관심 신호
+ 실사용 영향
+ 출처 다양성
+ 논쟁성
+ 지속 가능성
        ↓
   이슈 우선순위
        ↓
서로 다른 이슈로 분리
        ↓
CARD 01 / CARD 02 / ...
```

개수는 사용자가 요청한 만큼 뽑되, 의미 없는 이슈를 억지로 채우지 않는다.

### 현재

- 범용 분야 검색 구조 정의
- 분야별 소스 후보 정의
- GitHub 별도 레이어 정의
- Codex용 GPTaku의 `search + research` 전략 채택
- **ChatGPT에서 동일 전략을 최대한 재현하는 테스트 방향 확정**

### 다음 단계

1. Codex 실행 환경에서 `gptaku-plugins-codex` 최신 상태 확인
2. `insane-search-codex` / `insane-research-codex` 실제 동작 검증
3. 공개 페이지 접근 실패 → 대체 경로 테스트
4. ChatGPT와 Codex 결과 비교
5. 품질이 확인되면 도리보고 검색 코드로 최소 구현

**검증되지 않은 자동화 코드를 크게 만들지 않는다. 작은 검색 실험 → 결과 확인 → 필요한 부분만 코드화한다.**
