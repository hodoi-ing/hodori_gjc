# 🔎 도리보고 검색 구조

도리보고의 검색 범위를 **AI 전용 → 분야와 주제에 따라 바뀌는 범용 이슈 탐색**으로 확장한다.

핵심은 사이트 10곳을 항상 똑같이 검색하는 것이 아니다.

> **주제 → 분야 판단 → 적합한 검색 소스 선택 → 이슈 후보 수집 → 교차검증 → 카드 생성**

---

## 1. DRT / DRI 검색 방식

### DRT — 주제가 있는 검색

사용자가 주제를 지정한다.

```text
DRT
주제: 닌텐도
개수: 5
기간: 최근 7일
```

검색기는 닌텐도에 맞는 게임·콘텐츠·커뮤니티·뉴스 소스를 우선 선택한다.

### DRI — 주제를 발견하는 검색

사용자가 분야만 지정하거나 전체로 요청한다.

```text
DRI
분야: 전체
개수: 5
기간: 오늘
```

검색기는 여러 분야의 최근 신호를 탐색하고, 실제로 관심을 받을 만한 이슈를 선별한다.

---

## 2. 분야별 검색 소스

고정된 10개 사이트를 모든 주제에 적용하지 않는다.

| 분야 | 우선 소스 예시 |
|---|---|
| 🤖 AI / 개발 | GitHub · X · Reddit · GeekNews · OKKY · 공식 문서 |
| 🎮 게임 | Reddit · Steam · X · 게임 전문 매체 · 공식 발표 |
| 📈 경제 / 금융 | Reuters · Bloomberg · 국내 경제지 · 공식 통계 · 관련 커뮤니티 |
| 🔬 과학 | Nature · Science · NASA · 연구기관 · 전문 커뮤니티 |
| ⚽ 스포츠 | 공식 리그/구단 · ESPN 등 스포츠 매체 · X · 커뮤니티 |
| 🎬 영화 / 콘텐츠 | Reddit · X · IMDb · 전문 매체 · 공식 발표 |
| 🇰🇷 한국 사회 이슈 | 국내 주요 언론 · 공식기관 · 커뮤니티 · 검색엔진 결과 |
| 🌎 글로벌 이슈 | Reuters · AP · BBC 등 주요 매체 · 공식기관 · 커뮤니티 |

위 목록은 **후보군**이다. 특정 사이트를 반드시 검색해야 한다는 뜻이 아니다.

---

## 3. 검색 엔진을 기본 입구로 사용

검색엔진은 특정 사이트에 직접 들어가는 것보다 **관련 자료가 어디에 있는지 발견하는 역할**을 한다.

```text
검색엔진
   ↓
관련 페이지 후보
   ↓
사이트/분야 분류
   ↓
원문 확인
   ↓
이슈 후보 생성
```

검색 결과가 특정 사이트에 막혀 있어도 검색을 중단하지 않는다.

- 검색 결과의 제목/요약으로 후보를 파악
- 같은 내용을 공개된 다른 출처에서 확인
- 공식 문서나 원자료가 있으면 우선 확인
- 접근이 불가능한 페이지는 우회 침투가 아니라 **대체 공개 출처**로 교차검증

---

## 4. GitHub는 별도 검색 레이어

AI·개발 분야에서는 GitHub를 일반 웹 결과와 별도로 확인한다.

```text
웹 검색
   ├─ 뉴스
   ├─ 블로그
   ├─ 커뮤니티
   └─ SNS

GitHub 검색
   ├─ Repository
   ├─ Releases
   ├─ Issues / PR
   ├─ 최근 커밋
   └─ 코드 / README
```

GitHub 후보는 다음을 확인한다.

- 최근 업데이트
- Release
- Star 증가 흐름
- Issue / PR 활동
- README에서 실제 해결하려는 문제
- 설치 및 실험 가능성
- 최근 커뮤니티 언급

**Star가 많다는 이유만으로 선정하지 않는다.** 지금 움직이고 있는지, 왜 관심을 받는지, 직접 써볼 가치가 있는지를 함께 본다.

## 5. GPTaku `insane-search` 검토 결과

검토 대상:

`fivetaku/gptaku_plugins`

이 저장소에는 Claude Code용 `insane-search`가 있으며, README는 차단된 공개 페이지에 대해 여러 접근 방식을 단계적으로 시도하는 검색 도구라고 설명한다. WAF/403/CAPTCHA/login wall 등을 만났을 때 public API reader, syndication gateway, TLS impersonation, headless browser 등을 순차적으로 시도하며 별도 API key가 필요 없다고 설명한다.

도리보고 관점에서는 **검색 범위를 넓히는 보조 레이어로 가치가 있다.** 특히 검색엔진에서 발견한 공개 페이지를 실제로 읽을 수 없는 상황의 보완책이 될 수 있다.

### 다만 원칙은 명확히 한다

도리보고가 사이트의 인증·접근통제를 불법적으로 우회하는 것을 목표로 삼아서는 안 된다.

사용 범위는 다음처럼 잡는다.

```text
공개 자료
  ↓
일반 fetch
  ↓ 실패
공개 API / RSS / 공개 미러 등
  ↓ 실패
허용되는 브라우저 접근
  ↓
그래도 확인 불가
  ↓
다른 공개 출처로 교차검증
```

`insane-search` 자체의 구현 방식은 **도리보고의 검색 원칙과 실제 실행 환경을 확인한 뒤 별도 어댑터로 검토**한다.

## 6. 도리보고에서의 GPTaku 위치

`gptaku_plugins` 전체를 도리보고에 넣는 것이 아니다.

```text
                    🐯 도리보고
                         │
                  DRT / DRI 요청
                         │
                 🔎 검색 오케스트레이터
                  ┌──────┼──────┐
                  ↓      ↓      ↓
               웹 검색  GitHub  GPTaku 검색 보조
                  │      │      │
                  └──────┼──────┘
                         ↓
                    이슈 후보화
                         ↓
                    교차검증
                         ↓
                    카드 생성
```

GPTaku는 **검색을 대신하는 중심 엔진이 아니라, 일반 접근이 막힌 공개 자료를 읽어야 할 때 사용하는 선택적 보조 수단**으로 둔다.

---

## 7. 최종 이슈 선정

검색 결과를 그대로 카드로 만들지 않는다.

```text
최근성
+ 실제 변화
+ 관심 신호
+ 실사용 영향
+ 출처 다양성
+ 논쟁성
+ 지속 가능성
        ↓
   이슈 우선순위
        ↓
서로 다른 이슈로 분리
        ↓
CARD 01 / CARD 02 / ...
```

개수는 사용자가 요청한 만큼 뽑되, 의미 없는 이슈를 억지로 채우지 않는다.
